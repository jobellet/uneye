# Hazards, measures and evidence (illustrative)

**Illustrative only.** Inspired by the structure of IEC 62304 / ISO 14971 (hazard → cause → risk control → verification →
residual risk). This is NOT a compliance claim, there is no intended use, no severity/probability scoring and no clinical
evaluation. It shows how each guard rule is traced to a requirement and to a test that really exists in this repository.

"Dangerous output" below = an emitted saccade event that is physiologically impossible on the unperturbed signal (no movement
< 10 deg/s, > 40 deg, > 150 ms), measured by `cpp/tools/fault_injection.cpp` on test set B (datasets 1+2, 120 trials each),
MacBook Air M1, clang 22.1.8 -O3, fixed seeds. Numbers: `docs/slides/data/fault_injection.csv` (network alone → engine + guard; noise limit 16 deg/s). The run with the first limit (23.1 deg/s) is kept in `fault_injection_ood23.1.csv`.

| ID | Hazard | Cause | Risk control (REQ) | Verification (TEST) | Measured | Residual risk |
|---|---|---|---|---|---|---|
| H1 | Saccade reported while the eye does not move | network stuck / dead (always "saccade") | REQ-01: a saccade label without movement (speed < 10 deg/s) too often → DEGRADED, the guard's own detector labels; events with peak < 10 deg/s are never emitted | `safety_guard` [12], `fault_injection` net_stuck | 243 → 0 | the guard's fallback detector can itself be fooled (H5) |
| H2 | Events from a frozen tracker signal | camera / driver freeze, both axes constant | REQ-02: both axes bit-identical for 50 samples → SAFE (no output) | `safety_guard` [4], [13]; `fault_injection` frozen | 77 → 0 | real saccades during and 1 s after a freeze are lost (recall 0.72 → 0.27) |
| H3 | Events from values at the tracker's range limit | saturation / clipping | REQ-03: an axis held beyond 30 deg (training max 27.9) for 5 samples → SAFE | `safety_guard` [3]; `fault_injection` saturation | 9 → 0 (clip at 2 deg) | clipping INSIDE the 30 deg rail is not detected as saturation; here it was caught as a frozen signal (`Flat`) because both axes sat on the clip value; ONE clipped axis alone is not detected |
| H4 | Wrong events because the sampling rate is wrong | tracker configured at 500 Hz, engine expects 1 kHz | REQ-04: measured mean sample interval differs > 10 % from nominal → SAFE | `safety_guard` [5]; `fault_injection` rate_correct | 0 events (SAFE 100 %) | **500 Hz data with 1 kHz timestamps cannot be seen from time stamps: 42 → 32 dangerous outputs. Not solved.** |
| H5 | False events under electrical interference | 200 Hz bursts on the signal | REQ-05: jumps > 1000 deg/s are invalid samples; input noise > 16 deg/s (calibrated on set A) → DEGRADED | `safety_guard` [2], [9]; `fault_injection` burst | 2 deg: 15 → 0; 0.1 deg: 120 → 46; 0.5 deg: 16 → 37 | **small bursts pass the input checks; at 0.5 deg the guard's own fallback detector is fooled. Not solved.** |
| H6 | False events in noisy data | poor calibration, other tracker | REQ-05 (same); noise limit 16 deg/s chosen on set A only (`cpp/scripts/calibrate_ood.py`: fewest dangerous outputs within 2 recall points) | `fault_injection` noise | σ 0.1 deg: 6 → 0; σ 0.05 deg: 36 → 0 (with the first limit 23.1: 28) | in noisy data the guard is DEGRADED more often: recall at σ 0.05 deg 0.22 → 0.13; noise between the training range and 16 deg/s is not flagged |
| H7 | Events in the wrong unit / gain | gaze in pixels or wrong calibration gain | REQ-06: amplitude > 40 deg and peak > 1000 deg/s events are dropped; OOD noise → DEGRADED | `safety_guard` [11]; `fault_injection` scale | ×10: 655 → 118 | **partly solved only**; the engine expects degrees |
| H8 | Late result used as if it were on time | OS jitter, overload | REQ-07: compute time over 1 ms → that sample is Invalid; 1 miss in 1 s → DEGRADED, 10 → SAFE (the engine reads no clock, the caller passes the time) | `safety_guard` [10]; `fault_injection` deadline; `bench_latency` | 14 → 0; 7 of 1e6 pushes > 1 ms on the M1 | the guard can only react to lateness that the caller measures; no WCET exists |
| H9 | Crash or unbounded delay from memory allocation at run time | heap use in the per-sample path | REQ-08: no allocation after construction | `zero_heap` (0 allocations over 100 000 hostile samples, engine + guard) | 0 | macOS build counts operator new/delete only (no glibc malloc hook); stack use not measured |
| H10 | Different output in the field than in the test | non-determinism | REQ-09: no clock, no randomness, no I/O in step(); same input → bit-identical output | `safety_guard` [14]; `gaze_engine` determinism section | identical | bit-identical only for the same compiler and flags; -O0 / -ffp-contract=off change outputs by up to 3.3e-6, never a label (`equivalence`, cpp/scripts/equivalence.py) |

Requirement IDs are introduced here; the rules themselves are in `cpp/include/uneye/safety_guard.hpp` (`GuardConfig`, `Reason`).
