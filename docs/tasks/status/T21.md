# T21 status — release pipeline and packaging (done by the integrator)

## Delivered
* `.github/workflows/eyelive-release.yml`: on a tag `eyelive-v*`, by hand (`workflow_dispatch`) and, for Windows only, on pull requests touching `cpp/app/**`. Matrix windows-2022 (MSVC, static runtime, Visual Studio generator), macos-14, ubuntu-24.04 (`-static-libstdc++ -static-libgcc`, Wayland off): fetch ImGui / GLFW, configure `Release` with `EYELIVE_PORTABLE=ON` and the GUI, build, `ctest -L eyelive`, offscreen GUI smoke test (Linux), signing steps that are skipped without secrets, `package.py`, artifact upload; on a tag a DRAFT GitHub release with the zips and a combined `SHA256SUMS.txt`. The Windows job has `continue-on-error` because it has never been run by the authors.
* `cpp/app/packaging/`: `package.py` (strip, ad-hoc `codesign` on macOS, dependency check, models, `INSTALL.txt` = `docs/eyelive/INSTALL_UNSIGNED.md`, `CLI.txt`, `THIRD_PARTY.txt`, per-file `SHA256SUMS.txt`, the zip and its `.sha256`, sizes printed; no packer), `check_dependencies.py` + `ALLOWED_DEPENDENCIES.txt` (macOS `otool -L`, Linux `readelf -d`, Windows `dumpbin /dependents`; fails on anything else), `THIRD_PARTY.txt` (Dear ImGui MIT, GLFW zlib, U'n'Eye), `SIGNING.md` (where a Windows certificate or an Apple Developer ID plug in; inactive).
* `cpp/CMakeLists.txt`: option `EYELIVE_PORTABLE` (no `-march=native`: a binary built on a runner must run on the users' CPUs; the development default is unchanged), an MSVC branch (`/MT` static runtime, `/utf-8`, `/bigobj`, `_USE_MATH_DEFINES`, `NOMINMAX`), the POSIX-only legacy tools and tests are not built on Windows, warning flags guarded for MSVC (also in `cpp/app/CMakeLists.txt`, `cpp/app/cli/CMakeLists.txt`).
