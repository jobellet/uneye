# T19 status — trigger engine (done by the integrator)

## Delivered
`trigger/src/trigger.cpp` (engine), `src/sinks.{hpp,cpp}` (UDP, log file, stdout, `null`), `include/eyelive/trigger_clock.hpp` (`trigger_host_now_s()` = seconds on `std::chrono::steady_clock`, the host clock of the whole interface), `tests/test_trigger.cpp`.
* Matching: `enabled`, class / `any_class`, anchor (`OnsetProvisional` matches provisional events, `OnsetFinal` and `Offset` final events; a retraction, i.e. a final event with `confidence = 0`, never fires), amplitude range, per-rule refractory (anchor times of two accepted events).
* Timing: `sample_arrival_host_s` of `on_event` is the host time at which the ONSET sample arrived; `requested = arrival + delay_ms` (OnsetProvisional / OnsetFinal) or `arrival + (t_offset - t_onset) + delay_ms` (Offset). If `requested` is already in the past the trigger fires at once and is logged with `late = true`.
* One timer thread: min-heap of pending triggers, `condition_variable` sleep until `spin` before the due time, then a spin on the clock. `spin` is adaptive (starts at 1.5 ms, follows the measured oversleep of the OS timer, 0.1-25 ms) because a fixed 100 us spin was not enough: the first version had a median error of 1.2 ms on macOS.
* Sinks: `udp:<ipv4|localhost>:<port>` (non-blocking socket, created at `start()` or when rules change while running), `log:<path>` (append, flush each line), `stdout`, `null` (counts only). Payload placeholders `{t}` (anchor event onset time, 6 decimals), `{amp}` (3 decimals), `{cls}`; unknown placeholders are left as they are. A bad sink spec in `set_rules` does not throw: the rule gets a `null` sink and `last_error()` tells why (the `ITriggerEngine` interface has no error channel).
* `set_rules` while running is safe (rule sets are immutable snapshots shared with pending triggers; sinks of unchanged specs are reused; refractory state is kept by rule name).
* `stop()` joins the timer thread and DROPS the triggers whose delay has not elapsed (an experiment that ends must not fire late triggers); triggers already due are sent first.

## Deviations and open points
* **Amplitude ranges need a final anchor.** Provisional events carry no amplitude, so a rule with `amp_min_deg > 0` or `amp_max_deg < 1e8` never matches them. A microsaccade trigger therefore fires after the final event is known (`OnsetFinal` or `Offset`), not 3-6 ms after the onset. The GUI should say so.
* The offset anchor assumes that the tracker clock and the host clock advance at the same rate (it adds `t_offset - t_onset` to the host arrival time of the onset sample).
* The queue holds 4096 pending triggers; beyond that triggers are dropped (counted internally) rather than allocating on the event path.
* Windows (Winsock) branch written against the documentation, not built or run. No hardware sinks (not in scope).
* The independent `agy` review was not possible (headless mode could not read files).
