# T12-T17 status — GUI shell and tabs (done by the integrator)

All of `cpp/app/gui/` is one executable `eyelive` (the tabs register through static objects, so every source under `gui/src/` is compiled straight into the executable rather than into a static library that a linker would trim). Build: `sh cpp/third_party/fetch.sh && cmake -S cpp -B build -DEYELIVE_BUILD_GUI=ON && cmake --build build`.

## Shell (T12)
* `shell_main.cpp`: GLFW + OpenGL 3.2 core + Dear ImGui; tab bar from `tab_registry()` sorted by `order()` ("no tabs" when empty); status bar (REC / idle, rate, samples, recorded / planned time, memory, CPU, latency, dropped packets, warning); **render on demand**: a frame is drawn on an input event, for the first 3 frames, 2 frames after any interaction, at 30 Hz while the visible tab says `wants_redraw()`, and once per second otherwise; HiDPI: UI scaled on Windows / Linux, left to the framebuffer scale on macOS.
* `--mock` (synthetic `MockEngine`: simulator gaze, truth events, fake trainer and trigger log), `--demo` (the REAL engine on a simulated session of 60 s recorded as fast as possible and pre-labelled by `hmm_accel`), `--tab <title>`, `--shot file.ppm [--frames N]` (hidden window, `glReadPixels`, binary PPM), `--size WxH`, `--settings file`, `--run-seconds S` (exit after S seconds, prints frames and CPU). Models are looked for next to the executable or in a repository checkout (`models/`, `cpp/models/`).
* `Settings` (`settings.hpp`): `~/.eyelive/settings.txt`, key=value, rewritten on change (the Acquire inputs and the trigger rules persist).
* `widgets.cpp`: the trace plot (x, y and speed with min / max decimation per pixel column, events as bands, wheel zoom, drag pan, double click = jump to the end), the gaze map, loss curves; no plotting library.

## Tabs
* **Acquire (T13)**: source (simulator / file replay / UDP), declared or measured rate, planned duration, preallocation summary (`recorder_sizing`, updated while typing; free disk space, refreshed every 5 s), units (degrees, pixels with a known pixels-per-degree, pixels with the screen geometry, automatic), session file, detector at start, Start / Stop with the error text of `start()`.
* **Live (T14)**: scrolling traces with events, speed, gaze map of the last N ms, event list, live statistics; follow mode.
* **Detection (T16)**: the registered detectors with classes, decision delay and provisional latency, "Use now" (hot swap), the unit scale in use, convention calibration to the expert's corrections (`fit_calibration_to_expert`; the calibrated events can be loaded into the Review tab).
* **Review (T15)**: pre-labeler choice and run (all or the visible window, in the background), select by click (plot or list), a Delete button and key that remove the event at once, add by clicking the start then the end (or dragging), move onset / offset (drag the edges), change class (buttons, keys 1-4), split (S), merge (M), undo / redo (Z / Y), mark the window reviewed (R), exclude it (X), next uncertain event (]), reviewed seconds against the 50 s target, agreement of the detector with the corrections (F1, kappa). Checked with scripted input (`--script`) and screenshots: select, delete (76 -> 75 events, band gone), two-click add (76 -> 77 events). A first version drew the signal shifted when the view started before 0 s (reported by the owner on a MacBook), fixed.
* **Train (T16)**: classes (default 3), seconds of data (default 50), rotation augmentation on by default (off switch), noise and gain, start from random / pretrained U'n'Eye / a model file, optimiser settings, progress and loss curves, Cancel, deploy as detector `user:<name>`.
* **Triggers (T17)**: rule table (class or any class, amplitude range, anchor provisional / final / offset, delay, refractory, sink udp / log / stdout, payload placeholders), persisted, applied at once; a warning when an amplitude range is combined with the provisional anchor; firing log with timing errors.
* **Predict (T17)**: the forecast of the eye position at +10 and +20 ms (gaze engine: two causal networks + landing tables, 1 kHz only) drawn over the measurement in real time (also in the Live tab), with its 80 % interval at the live edge and its error over the last 10 s against 'stays where it is' (engine test: median error 0.029 deg at +10 ms; during large movements 1.68 deg against 2.44 for staying); the latest forecast is published in the state block. The tab also explains how MATLAB / Psychtoolbox and PsychoPy read the state block.
* **Log (T17)**: engine statistics, warnings, scale and trigger timing table.

## Not done / limits
* Not tested: interactive mouse and keyboard editing in the Review tab (only rendering was checked by screenshot, the editing logic uses the T07 API tested elsewhere); Windows and Linux GUI builds (CI builds and screenshots on Linux with Xvfb; Windows will be built by the release workflow, T21); high-DPI layouts other than macOS retina.
* The Detection tab cannot enter the unit scale by hand while a session runs (no engine call for it): it is set in Acquire before starting. Applying a fitted calibration goes through the Review tab (`load_prelabels`).
* `MockEngine` and the tabs use the real contracts only; no tab includes an engine implementation (the Train tab reads `models_dir()` from the detector module to find the pretrained models).
