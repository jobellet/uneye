# T18 status — engine (done by the integrator)

## Delivered
`engine/src/engine.cpp` (`make_engine()`), `src/platform.hpp` (process CPU time, lower thread priority), `include/eyelive/engine_hooks.hpp` (`make_engine_with_trainer`, for tests), `tests/test_engine.cpp`. The module links recorder, source, state, the three detector modules, annot, calib, train, trigger and the uneye engines.
* **Threads.** Source thread (read, stamp the arrival on the monotonic host clock, write the recorder; a paced `sim` source sleeps to its sample times) -> the recorder is the queue -> analysis thread, woken after every batch of samples (so the detection latency is not bounded by a polling period). The active detector runs every 5 ms (every wake-up when it publishes provisional events itself); a `fast_threshold` detector runs in parallel at every wake-up and supplies the PROVISIONAL events when the active detector has none (they go to the trigger engine and the state block; the final events come from the active detector).
* **Start-up.** `source` is opened; with `rate_hz == 0` the rate is measured with `RateEstimator` on the first samples (kept and recorded), then `Recorder::create` preallocates the file and fails loudly with the system message; the state block is initialised; the detectors are reset with the session and the scale.
* **Events.** Final events -> recorder events table, per-sample `label`, state block (`publish_event`), trigger engine; blink events (class 2) from runs of >= 3 invalid or `kFlagBlink` samples; a per-sample state block update after every wake-up; health word and latency percentiles every 20 wake-ups.
* **Scale.** `deg_per_unit > 0`: used as given. `0`: once >= 20 final events and >= 10 s exist, a worker thread runs `select_scale` (U'n'Eye 1+2+3 against the unit-free HMM events of the last 60 s); the result is applied at the next wake-up (`stats().scale_estimated`, `scale_agreement`, `scale_low_confidence`, and a warning telling to enter pixels per degree by hand when the confidence is low).
* **Hot swap** (`set_detector`): the new detector is created and validated at once (error returned), runs over the whole recording so far on its own thread, and the analysis thread installs it when it has caught up, dropping the events with onset <= the last published offset. No sample and no event is lost.
* **Review.** `prelabel` runs a detector in batch on a copy of [from, to), adds the blink events and loads them with `ExpertLabels::load_prelabels`; `agreement_with_expert` and `fit_calibration_to_expert` use the reviewed ranges only; expert labels are written to the recorder (`set_expert`) at `stop()` and before training.
* **Training.** One `TrainTrace` per reviewed stretch of >= 0.25 s (positions multiplied by the scale, labels from `ExpertLabels::render(..., only_reviewed)`), `TrainConfig.deg_per_unit` = the scale in use; while acquiring, `n_threads = 1` and the trainer is started from a helper thread with a lowered priority (macOS QoS utility, Linux nice +10, Windows below normal; the worker thread inherits it). `deploy_trained_model(name)` saves `<session dir>/models/user_<name>.bin` + sidecar and registers the detector `user:<name>`.
* `available_detectors()` lists every registered id (cached); `stop()` joins everything, flushes the last events, writes the expert labels, closes the file (cleanly closed flag) and keeps the trace readable.

## Deviations and open points
* The recorder's own header keeps `deg_per_unit` as given at creation; when the scale is estimated later, only the state block and the detectors are updated (the session file header still says 1.0). The amplitudes of events published before the estimate are not corrected.
* The 5 ms hop of the contract applies to the active detector; `hmm_accel` decodes every 10 ms internally (CPU).
* `hmm_accel` is a pre-labelling detector with a publication delay of ~115 ms; for low-latency triggers the engine uses the fast detector's provisional events whatever the active detector is.
* Detector registrars of static libraries are kept by referencing the detector classes in `register_detectors()` (and `make_user_model_detector`).
* ASAN: the local toolchain (zig clang) does not provide AddressSanitizer, so only TSAN was run locally; CI (gcc / clang on Linux) runs both.
* `T07` shipped `ExpertLabels` without destructor or deep copy; the integrator added them to the contract header and `annotation.cpp`.
* Not done: Windows (`GetProcessTimes`, thread priority branches are written, not built); live UDP end-to-end (the UDP source has its own tests in T02); the independent `agy` review.
