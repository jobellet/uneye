# T09 status — trainer (done by the integrator after the Jules run failed)

Both parts (T09a layers + gradient checks, T09b training loop + model I/O) are in one change. Everything below was measured on an Apple M1 (8 cores), Release build with the repository's zig toolchain.

## Delivered
* `train/include/eyelive/train/layers.hpp`: header-only templates (scalar type R): Conv1d (same padding), UpConv1d (transposed, kernel = stride), MaxPool1d, ReLU, BatchNorm1d (training: batch statistics, running statistics with momentum 0.1 and unbiased variance), `softmax_mcloss` (the repository's MCLoss: mean over all B·K·T elements of target·log(clamp(p)), ignored samples have an all-zero target).
* `train/include/eyelive/train/unet.hpp`: the U'n'Eye U-Net with backward pass, Adam-compatible parameter lists, `state()` / `load_state()` in the `cpp/models/*.bin` order.
* `train/src/dataset.cpp`: ~1 s windows, validation split, rotation (angles π·(0.25 + 2i/n), i < n; 4 by default), optional noise and gain augmentation, velocity input, event F1 / kappa.
* `train/src/trainer.cpp`: `make_trainer()`, worker thread, `cancel()`, per-epoch progress, recipe of `uneye/classifier.py::train` (Adam lr 1e-3, 10 minibatches per epoch, L2 0.001, validation loss each epoch, learning-rate halving and restoring the best weights when the validation loss is not below the mean of the last 3, stop after `patience` consecutive failures).
* `train/src/model_io.cpp`: `save_bin` (the `.bin` layout read by `uneye::make_native_engine`, unchanged) + `<model>.json` sidecar (window, classes, ks, mp, deg_per_unit, rate, epochs, validation scores, number of training windows); `load_bin` for transfer learning (if the class count differs, the output layer keeps its random initialisation).
* `cpp/scripts/export_unet_golden.py` and `train/tests/golden_unet_grads.txt` (0.85 MB, double precision).

## Deviations and open points
* The validation loss uses the batch-norm running statistics (evaluation mode). The original computes it with batch statistics because it never calls `net.eval()`; evaluation mode matches what the deployed detector computes.
* `save_model()` waits for the worker thread to finish (it joins it); call it after the final progress callback.
* The 3-class test only checks that training runs and saves (3 epochs, on synthetic data); a real accuracy check for blinks needs recorded data.
* Not tested here: Windows build, ThreadSanitizer (CI runs the sanitizer jobs on the whole `eyelive` label).
* `fit` on very short data: fewer than two ~1 s windows gives `failed = true` with a message (the GUI should show it).
