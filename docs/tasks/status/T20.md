# T20 status — CLI and end-to-end tests (done by the integrator)

## Delivered
`cpp/app/cli/src/cli_main.cpp` (`eyelive_cli`), `cli/README.md` (documented examples), `cli/tests/test_cli_e2e.cpp`, `cli/CMakeLists.txt` (ctest label `cli`).
* Options: `--udp <port>` / `--replay <csv> [--speed x]` / `--sim [--rate Hz]`, `--bind`, `--duration`, `--samples`, `--detector`, `--session`, `--scale <deg_per_unit>|auto`, `--rate-hz`, `--triggers <file>` (one rule per line, `key=value;...`), `--prelabel-seconds N`, `--events-out <csv>`, `--train` (pre-label, mark as reviewed, train, deploy as `user:cli`), `--models-dir`, `--quiet`. Prints each final event while recording and a summary line; exit code 0 / 1 / 2 (documented).
* A simulation runs as fast as possible unless `--speed` is given, and `--duration` then counts seconds of data; a replay runs at real time by default; a stream that stays silent for 10 s ends the run.

## Deviations and open points
* The streaming (published while recording) events are not compared one by one with the reference because the 1 s golden traces end before the ~115 ms publication delay of `hmm_accel` has elapsed for the last events; the batch events (pre-label of the whole recording) are the compared ones.
* The `--train` example validates on a few windows only (F1 0.0-0.4 on 15 s of simulated data): it is a smoke test of the pipeline, not a benchmark.
* UDP ports are derived from the test's process id (41000 + pid % 2000); a busy port makes the test fail rather than hang.
* Windows: the end-to-end test is skipped (POSIX sockets and `fork`-less shell in the test); the CLI itself has no POSIX-only code except the signal handler.
