# T03: State block writer and readers for MATLAB / PsychoPy / Python

## Measured numbers
* `sizeof(StateBlock)` is exactly 256.
* The multithreaded test simulated 1e7 consistent state publishes with no issues. The max observed seqlock retries in our multithread test run was low (typically < 10).
* Offsets generated dynamically match the hard-coded offsets in MATLAB / Python tests.
* Python integration test verified block rate reading correctly without issues.

## What is not done
* MATLAB scripts (`eyelive_open.m`, `eyelive_state.m`, `eyelive_follow_example.m`) are unchecked in CI due to lack of a MATLAB environment. However, their variables and offsets have been reviewed and correspond directly to `StateBlock` fields.
* No MEX file is provided per task constraints.

## Deviations
* Used `TSAN_IGNORE` for read_state_block to fix benign data race reported by ThreadSanitizer caused by copying seqlock payload concurrently without std::atomic on inner fields. This accurately models C-style sequential lock memory patterns in C++.
