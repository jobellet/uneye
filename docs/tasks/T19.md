# T19 — Trigger engine: rules, delays, UDP / log sinks, latency log

Phase 1 · size M · depends on: none (only the contract headers) · branch `jules/T19-<short-name>` · pull request title `T19: Trigger engine: rules, delays, UDP / log sinks, latency log`

## Goal
Implement `ITriggerEngine` (`trigger.hpp`): rule matching, delayed firing with a dedicated timer thread, sinks, and an honest log of requested versus actual firing times.

## Read first
* `docs/tasks/README.md` (rules for every task: read it first)
* `cpp/app/include/eyelive/trigger.hpp`, `docs/EYELIVE_ROADMAP.md` sections 4 and 12.4

## You own (and may change ONLY these paths: CI rejects anything else)
* `cpp/app/trigger/**`
* `docs/tasks/status/T19.md`

## What to implement
`trigger/src/**`: rule matching (class, amplitude range, anchor, refractory), a min-heap of pending actions, a timer thread on `std::chrono::steady_clock` with a short spin for the last 100 us, sinks `udp:<host>:<port>` (socket created at `start`), `log:<path>` (append, flush each line) and `stdout`; payload placeholders `{t}`, `{amp}`, `{cls}`; the `late` flag when the event arrives after the requested fire time (it then fires at once and the entry is marked); `on_event` is thread-safe and lock-light.

## Files you create
* `trigger/src/**`, `trigger/tests/test_*.cpp`

## Acceptance tests (all must pass; ctest label = module name)
* 200 triggers at +10 ms after a synthetic onset: median error < 1 ms, p95 < 3 ms on the CI runners (printed; thresholds are loose because CI machines are noisy; the measured values go in the status file)
* refractory, amplitude range (microsaccade < 1 deg), class and any-class matching, provisional against final anchors, `late` flag, rule changes while running, enable / disable
* the UDP sink delivers the payload with substituted placeholders to a loopback socket in the test
* no allocation in `on_event` after the first call (count with a hook in the test); TSAN clean

## Do not
* Do not add hardware sinks (serial, parallel port, DAQ): a later task.
